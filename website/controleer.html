AnonyMate naar de browserversie

Zo controleer je dit zelf

Wij beloven dat je data je computer niet verlaat en dat de app op deze site is gebouwd uit de openbare broncode. Geloof dat niet op ons woord: dit zijn de manieren om het na te gaan, van eenvoudig (een paar klikken) tot grondig (een eigen build).

1Wat wordt beloofd

  • De browserversie op anonymate.nl/app/ rekent volledig in je eigen browservenster. Je dataset, en alles wat daaruit volgt, wordt nergens heen gestuurd, ook niet naar anonymate.nl. Er wordt alleen gedownload: de app zelf en (straks) openbare brondata.
  • De broncode is openbaar (GitHub, EUPL 1.2), en wat op deze site draait, is daaruit gebouwd. Elke bouwstap staat in de repository en is te herhalen.

2Kijk zelf naar het netwerkverkeer

Dit kost vijf minuten en vraagt geen technische kennis.

  1. Open de app en druk op F12 (Mac: Cmd+Option+I). Kies het tabblad Netwerk (Network) en laad de pagina opnieuw.
  2. Je ziet de bestanden van de app langskomen: de pagina, de rekenkern, Python en de bibliotheken. Alles komt van anonymate.nl, van geen andere host.
  3. Wacht tot de app klaar is en open dan je dataset of de oefenmodus. Wis de lijst en doe een toets: er komen geen nieuwe verzoeken bij. Dat is de kern van de belofte.
  4. Wie het zeker wil weten: zet na het laden de wifi uit (of vliegtuigmodus aan). De toets werkt gewoon door.

3De Content-Security-Policy: wat de pagina mag

De pagina heeft een regel voor je browser meegekregen die het onmogelijk maakt om iets naar een andere plek te sturen, ook als er per ongeluk of met opzet code zou zijn die dat wil. In de app staat hij leesbaar onder Wat deze pagina mag. Zo luidt hij nu:

default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; connect-src 'self'; worker-src 'self' blob:; img-src 'self' data: blob:; style-src 'self' 'unsafe-inline'; form-action 'none'; base-uri 'none'; object-src 'none'

Wat dat betekent: scripts en bestanden komen alleen van anonymate.nl (default-src 'self', script-src 'self'); de pagina mag alleen verbinding maken met anonymate.nl zelf (connect-src 'self'), dus geen upload naar een andere server; er zijn geen formulieren die ergens heen posten (form-action 'none') en geen plug-ins (object-src 'none'). 'wasm-unsafe-eval' is nodig om Python (WebAssembly) te draaien. De browser dwingt dit af: de beperking zit dus in de pagina zelf, niet alleen in onze belofte.

4De build narekenen: is de site gebouwd uit de broncode?

Linksonder in de app staat versie … · commit …: dat is de commit waaruit de site is gebouwd. Dezelfde gegevens staan in manifest.json: van elk bestand de grootte en de SHA-256 (een vingerafdruk van de inhoud). Bouw je zelf dezelfde commit, dan moet je precies dezelfde vingerafdrukken krijgen. De build is daarvoor reproduceerbaar: dezelfde commit in dezelfde omgeving geeft byte voor byte dezelfde bestanden (GitHub controleert dat bij elke wijziging).

Voor wie de opdrachtregel kent

Nodig: Git en Python 3.13. De referentiebuild is die van GitHub Actions (Linux); de versies van het bouwgereedschap staan vast in web/bouw-constraints.txt.

git clone https://github.com/anonymate-nl/anonymate
cd anonymate
python -m venv .venv && . .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -e . -c web/bouw-constraints.txt
python web/controleer.py

Het script haalt manifest.json van anonymate.nl, leest daaruit welke commit is uitgerold (staat je checkout er niet op, dan zegt het git checkout <commit>), bouwt web/dist opnieuw, vergelijkt elk bestand met de site, en downloadt elk bestand van de site om te zien dat het klopt met het manifest. Uitkomst bij succes: gelijk: wat op https://anonymate.nl/app/ draait, is gebouwd uit commit …. Bij een verschil noemt het welke bestanden verschillen.

Los van het script kan het ook: de sha256sum van een bestand uit app/ moet gelijk zijn aan de waarde in manifest.json.

Daarnaast draait elke week een geautomatiseerde controle (workflow “controle”) die precies dit doet en faalt als de site afwijkt.

5De herkomst: is dit echt door GitHub gebouwd?

Bij elke uitrol legt GitHub Actions vast dat manifest.json (en de belangrijkste bestanden) is gebouwd uit deze repository en deze commit: een attestatie (SLSA-herkomst, ondertekend via Sigstore). Zo weet je dat de bestanden niet ergens anders zijn gemaakt en daarna op de site zijn gezet.

Voor wie de opdrachtregel kent

Nodig: de GitHub CLI (gh).

curl -O https://anonymate.nl/app/manifest.json
gh attestation verify manifest.json --repo anonymate-nl/anonymate

Bij succes staat er welke workflow en welke commit het bestand hebben gebouwd. Die commit moet gelijk zijn aan bron.commit in het manifest.

6Python zelf: Pyodide, vastgezet

De rekenkern draait in Pyodide (Python in WebAssembly). Wij hosten een vaste versie zelf (nu 314.0.7) en laden niets van een CDN. De build controleert elk bestand tegen de officiele release: de pakketten (numpy, pandas, duckdb, h3 en wat ze nodig hebben) tegen de SHA-256 in pyodide-lock.json van Pyodide, en de runtimebestanden tegen de waarden hieronder. Die staan in web/pyodide-sha256.json en zijn gemaakt van de officiele release 314.0.7. Klopt er iets niet, dan mislukt de build.

7Wat dit (nog) niet dekt

  • Je browser en besturingssysteem vertrouw je. Deze controles gaan ervan uit dat ze doen wat ze zeggen.
  • GitHub Pages en GitHub zijn de host en de bouwer. De attestatie en de weekcontrole maken misbruik zichtbaar, maar voorkomen niet dat er tussen twee controles iets anders wordt geleverd. Wie dat wil uitsluiten, draait de app uit een eigen build (python web/maak.py, dan python -m http.server -d web/dist).
  • De broncode zelf is nog niet inhoudelijk door derden beoordeeld: een gelijke vingerafdruk bewijst dat de site uit de broncode komt, niet dat de broncode goed is.
  • Het Windows-programma is nog niet ondertekend (Windows waarschuwt bij de eerste start) en de build ervan is nog niet reproduceerbaar. Dit hele verhaal geldt voor de browserversie.
